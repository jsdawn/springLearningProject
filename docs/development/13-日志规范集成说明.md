# 日志规范集成说明（阶段12 · 三）

> 对应学习路线阶段12③（P4 最后一部分）：统一日志格式、traceId 贯穿、userId 落日志。前置：阶段4 网关鉴权（X-Auth-\* 头注入链路）、阶段12① RBAC。  
> 涉及服务：gateway-service、order-service、user-service、product-service、common-auth、common-core。

## 目标

四个服务此前零日志配置，全是 Spring Boot 默认控制台格式。本篇解决三件事：

1. **统一格式**：所有服务一条 log pattern，日志肉眼可读、可 grep
2. **traceId 贯穿**：一个请求经网关 → order → Feign → user/product，全链路日志能用同一个 traceId 串起来
3. **userId 落日志**：每条请求日志直接看到操作者，报障不用先反查 token

## 总体设计

```
客户端
  │
  ▼
网关 TraceIdGlobalFilter（order 最小，先于鉴权）
  ├─ 无 X-Trace-Id 头则生成（UUID 去 - 取前 16 位）
  ├─ 写入请求头透传下游 + 写入响应头回传调用方
  └─ 日志显式打印 traceId（WebFlux 下 MDC 不可用，见下文）
  │
  ▼  X-Trace-Id 头
下游服务 TraceIdFilter（common-core，order=HIGHEST_PRECEDENCE）
  ├─ 读 X-Trace-Id（直连端口时自生成）→ MDC.put("traceId")
  ├─ 读 X-Auth-UserId → MDC.put("userId")
  ├─ 响应头回传 X-Trace-Id
  └─ finally MDC.clear()
  │
  ▼  Feign 调用
FeignTokenRelayConfig 追加透传 X-Trace-Id
  └─ MDC.get("traceId") 直接取——同步 Feign 跑在请求线程上，MDC 可用
```

**MDC 是核心机制**：SLF4J 的 MDC 基于 ThreadLocal 存键值对，logback pattern 里 `%X{traceId}` 自动取值——业务代码不用改任何一行日志，格式自动带上。

## 实现要点

### 1. 公共日志配置放 common-core，服务端只 include

`common-core/src/main/resources/logback/logback-base.xml`：定义 pattern、CONSOLE + FILE（按天滚动保留 7 天）两个 appender，`springProperty` 读 `spring.application.name` 做日志前缀和文件名。

三个 Servlet 服务各放一份 4 行的 `logback-spring.xml`：

```xml
<configuration>
    <include resource="logback/logback-base.xml"/>
</configuration>
```

改一处格式四个服务（三个）同时生效。**注意必须叫 `logback-spring.xml`**：`springProperty` 是 Spring Boot 对 logback 的扩展，只有 `-spring` 变体才支持，普通 `logback.xml` 会报错或被 Boot 提前初始化绕过扩展。

**网关是例外**：gateway 不依赖 common-core（Servlet 与 WebFlux 栈隔离，引入 common-core 会把 spring-webmvc 拉进响应式应用），无法 include 公共 base——维护一份独立完整的 `logback-spring.xml`，pattern 手工对齐。这是「格式统一」里唯一一处复制粘贴，文档里显式记录避免将来只改一边。

### 2. 常量与命名约定

- 头名 `X-Trace-Id` 定义在 common-auth `AuthConstants.HEADER_TRACE_ID`（网关和下游共同的依赖，头部契约单点维护）
- MDC key 固定 `traceId` / `userId`，与 pattern 里 `%X{traceId}` / `%X{userId}` 一字不差——改名要同步 TraceIdFilter、Feign 拦截器、logback-base.xml 三处

### 3. 过滤器顺序

`TraceIdFilter` 用 `@Order(Ordered.HIGHEST_PRECEDENCE)`，早于 `LoginUserContextFilter`（HIGHEST_PRECEDENCE + 10）和一切业务过滤器，保证过滤器链里任何一层打的日志都已带 traceId；`finally MDC.clear()` 防止 Tomcat 线程池复用导致日志串请求。

`userId` 直接读 `X-Auth-UserId` 头而不是从 `LoginUserHolder` 取——后者的值要等下一个过滤器才写入，TraceIdFilter 抢跑在读头上更简单，也避免两个过滤器产生顺序耦合。白名单请求（登录/注册）和 Feign 内部接口（`/internal`）没有该头，userId 显示 N/A，符合预期。

### 4. 网关为什么不用 MDC

MDC 基于 ThreadLocal，WebFlux 一次请求的处理会跨多个 EventLoop 线程切换，MDC 值会丢/串。网关侧选择：traceId 写进请求头/响应头，网关自己的日志（`RequestLogGlobalFilter`）显式拼接 traceId。这也是响应式栈日志追踪的通用思路——上下文随数据流走（Reactor Context），不依赖线程。

### 5. Feign 透传

`FeignTokenRelayConfig` 原本只透传 `Authorization`，追加一段：`MDC.get("traceId")` 非空则塞进 `X-Trace-Id` 头。**成立前提是同步 Feign**：Feign 同步调用执行在 HTTP 请求线程上，MDC 值还在；若将来切响应式客户端（WebClient），此法失效，需在构造请求时显式传递。

## 踩坑与边界

- **`logback.xml`（无 -spring）里用 springProperty 会解析失败**：Boot 对 `logback-spring.xml` 才注入 Spring 环境，命名是硬约定。
- **include jar 内资源**：`<include resource="logback/logback-base.xml"/>` 按 classpath 查找，common-core 的 resources 目录随 jar 发布即生效；若发现不生效先确认依赖的是源码模块输出而不是旧的 maven install 产物。
- **traceId 不做全链路强校验**：学习期「网关或首个入口生成 + 尽力透传」即可；真正的分布式追踪（采样、span、时序图）是阶段13 Sleuth/Zipkin 的事，本篇只解决「日志找得到同一条请求」。
- **生成 traceId 用 UUID 前 16 位**：全局唯一性对排查够用且日志里短一截；要跨系统对账再上完整 UUID 或雪花 ID。
